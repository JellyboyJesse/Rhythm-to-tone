# Rhythm Into Tone: notes for Claude

A web instrument where a looped rhythm, sped up, becomes a tone whose timbre is the rhythm. Served by GitHub Pages straight from `main`, with no build step. Everything is in `index.html`, apart from the install files (`manifest.webmanifest`, `icon.svg`, `icon-*.png`) that let it be added to the Dock on a Mac or installed on a phone.

## What Jesse wants from it

- An **accurate representation of the maths, not a faked one**. The sound engine, the wheel and the Fourier circles must all come from the same loop data. Don't add crossfades, mode switches or drawings that only look right. The spectrum panel was dropped (Jesse found it added little); the Scope shows the measured output instead.
- The goal is a **fused timbre**. Phase-locked rings make one periodic tone. Detune is the honest way to split it.
- LFOs on everything. A sequence on any dot, and a window that lists them.
- His main machine is a MacBook Pro (Retina, 15-inch, Late 2013, 16 GB) on macOS Big Sur. Chrome stopped updating there at version 138 and Safari has no Add to Dock, so build for Chrome 138 and current Firefox. It must also work on an Android phone (about 390 px wide, no sideways scroll), in both light and dark themes. The older 4 GB Linux laptop was the earlier target; he has not said whether it still matters.

## How index.html is built

1. **Shared maths (top of the script).** These are run on the page *and* copied into the AudioWorklet with `Function.prototype.toString`, so they may only use each other and built-ins. If you add one the Engine needs, add it to the `WORKLET_SRC` list too.
   - **The functions:** `frac`, `clamp`, `rnd`, `setShapes`, `lfoVal`, `lfoAmt`, `lockVal`, `newEff`, `effParams`, `euclidPattern`, `ringPos`, `ringDots`, `dotF`, `dotS`, `dotWheel`, `dotSliceA`, `dotSliceN`, `wtMake`, `degSemi`, `chordN`, `chordDeg`, `sqHits`, `sqKey`, `dotSeed`, `dotLv`, `dotAmp`, `dotTurn`, `dotPitch`, `dotLen`, `seqStep`, `applyMsg`.
   - **The `Engine` class.**
   - Two shared constants are written into `WORKLET_SRC` by hand ahead of the functions: `USHAPES` (the custom LFO shapes) and `SCALES` (the scales sequences use, as semitone lists).

   Do not use `eval`/`new Function`: some hosts block it.
2. **Custom LFO shapes.** `state.shapes` has eight slots, each null or `{name, smooth, pts}` with 32 points from -1 to 1 (`newShape`, `sanShape`). Anywhere an LFO shape is stored (`lfo[key].shape`, the dot LFO shapes `pls`/`lls`, an instrument modulator's `shape`), the value may be `'U1'`…`'U8'` as well as a built-in name (`okShape`). `lfoVal` reads the slot from `USHAPES`; `setShapes(state.shapes)` fills it on the page, and `Engine.setState` does the same in the engine. An empty slot gives 0. They are drawn in the Library panel's LFO shapes tab, and each filled slot shows as a numbered button in every LFO's row of shapes (`shapeBtns`, buttons with `data-u`).
3. **`effParams(S, t, step, E)`** turns saved state into the values in force at time `t`. It works in three layers: base values, then sequencer locks for the current step, then LFOs. It fills `E` in place, so it creates no garbage on the audio thread. Keep it allocation-free.
3. **`Engine`.** One phase clock and four rings. Each hit starts a Gaussian-windowed sine grain at its exact sub-sample time. Grains run by recurrence, and each keeps the F and σ it started with. A ring's rotation offset (`off`) shifts its phase, and hits crossed by rotation alone are skipped. The engine counts loops for the sequencer's Loops clock. A soft limiter only acts above 0.8.
   **Per-dot settings.** Each ring has `dp` (pitch offset, semitones, ±24), `dl` (length offset, octaves, ±2) and `da` (level, 0–1), 16 slots each. A dot is numbered by its order in the unrotated pattern (`ringDots`), so its settings travel with it when the ring rotates. Offsets are relative to Click pitch and Click length, so LFOs and the sequencer still move every dot. `dotList`/`heardMag` give the exact click spectrum (each dot's own click spectrum with its 3σ delay phase, summed). No panel draws it any more, but the tests check the engine against it, and the circles use `dotList`. A dot is edited by clicking it on the wheel (`#dotBox`). Each dot also has its own LFO on pitch (`pld` depth in semitones, `plr` rate, `pls` shape) and on length (`lld` in octaves, `llr`, `lls`). `dotPitch`/`dotLen` are the one place these are worked out, for the engine (at the moment a click starts) and for the page (`dotList(E,t)`). Each dot's LFO has its own start phase (`dotSeed`). Three more dot LFOs work the same way through `dotLv`: level (`ald`/`alr`/`als`, read by `dotAmp`), a sample's start (`sld`/`slr`/`sls`, in `dotSliceA`) and an inner wheel's turn (`tld`/`tlr`/`tls`, in octaves, in `dotTurn`). A sample's slice length is moved by the Length LFO.
   **Wheels inside dots.** Every dot has a kind, `dk`: `'click'` plays one click, `'wheel'` plays the wheel kept in `kids[d]` (`{rings:[4 rings]}`, each ring shaped like a top ring, so its dots can hold wheels again). `dt` is the inner wheel's one turn, as a fraction of the turn of the wheel it sits in (1/64–1). Wheels nest three levels below the top (`dotWheel(r,d,depth)`). More kinds (a sample, a bare impulse) are meant to be added to `dk` later. When a playhead crosses a dot, `Engine.fire` sets down the inner wheel's dots at their exact times in a queue of pending dots (no allocation) and each fires the same way when due. A turn is one-shot, keeps the length it started with, and may overlap the next dot. Level multiplies and pitch and length add up on the way down. Inner rings are plain saved values: the ring LFOs and sequencer lanes act on the top wheel only (dot LFOs work at every level). `dotList` expands the same tree, so the circles stay exact; the tests check the engine against it three levels deep.
   **Samples and impulses.** `dk` can also be `'sample'` or `'impulse'`. A sample dot plays a slice of the recording in slot `ds[d]` (0–7): it starts at `dss[d]` and lasts `dsn[d]` (both 0–1 of the recording) times 2^Length. `Engine.slice` hands it to `Engine.note`, so it runs through the same voice pool as an instrument, with that slot's playback settings: `state.smpp[slot]` (made by `newSmpPlay`, checked by `sanSmpPlay`, never null). These are shaped like an instrument (play mode, ADSR, filter, drive, modulators) plus `cut` (a new hit fades the one before it over 4 ms; the default) and `hold` (how long Held, Loop and Ping-pong are held, in turns of the wheel the dot sits on). In one-shot and reverse the release is timed to end as the slice ends. The loop region is the slice. `Engine.SP0` is the fallback when a patch has no `smpp`. `setSample` fades any voice still playing the old recording, and `stopAll` (the `stop` message) fades everything. Pitch is playback speed; Click pitch and Click length do not apply. An impulse dot writes one band-limited spike (a windowed sinc, 8 samples late, `Engine.spike`). Recordings are mono `Float32Array`s kept in IndexedDB (`rit-samples-v1`), never in the patch; the page holds them in `samples[]` and sends each to the engine with a `smp` message (`applyMsg`). `dotSliceA`/`dotSliceN` are the one place the slice is worked out. Click overlap compensation (`comp`) applies to clicks only.
   **Instruments.** `dk` can also be `'inst'`: the dot plays a note on instrument slot `di[d]` (0–7). The eight instruments are part of the patch (`state.inst`, each made by `newInst` and checked by `sanInst`; the key list is in the comment above `newInst`). `Engine.note` starts a voice from a fixed pool of 32 (`vo`): source (band-limited oscillator, or a sample with play modes one-shot, held, loop, ping-pong, reverse), then a state-variable filter with its own envelope, then the ADSR envelope. Pitch is the note in semitones from the root, level is velocity, and the note is held for a quarter of the turn of the wheel the dot sits in, times 2^Length. Poly takes the oldest voice of the slot when it runs out; mono and legato keep one voice per slot. The engine reads the instrument from `S.inst` at note-on, so an edit is heard from the next note. A third source is a wavetable (`src:'wt'`): `wt` names a built-in table (`wtMake`: 16 frames of 2048 samples, built in `setState`, never at note-on) or `'smp'` (a sample slot cut into 2048-sample frames), and `wp` is the position, mixing two neighbouring frames. Tables are not mip-mapped, so high notes can alias. Each instrument has up to eight modulators (`mods`, made by `newMod`, checked by `sanMod`): type `lfo`, `draw` (16 drawn points, smooth or stepped), `wheel` (reads the level, pitch or length of the dot a top ring's playhead last passed) or `rand` (a new value per note); clock `hz`, `loop` (cycles per loop) or `note` (one pass over the note). `Engine.modv` gives a modulator's value. Pitch, filter cutoff and resonance, wavetable position, level, FM, ring, second oscillator level, sub and noise are modulated every 8 samples; the envelope stages, filter envelope stages and sample start are read once at note-on. The oscillator and wavetable can run in unison (`uni` copies spread by `udet` cents). A second oscillator (`o2w`, `o2s`, `o2f`) can be mixed in (`o2l`), push the first one's phase (`fm`) or multiply it (`ring`); `sub` is a sine an octave down and `nz` is noise. Filter types are low-pass, 24 dB low-pass (`lp4`, two stages), band-pass, high-pass, notch (`nt`) and comb (`cb`, a fed-back delay per voice). `drive` is a tanh stage after the filter. The envelope can have straight segments (`elin`) and can loop attack and decay while the note is held (`eloop`). `INST_PRESETS` are starting points laid over `newInst()`. Unison ratios, drive and the second oscillator's ratio are worked out at note-on. Not built yet: Click and Wheel as sources, the Follow modulator, pan, effects.
   **Which wheel is on screen.** `view` is a path of dots from the top; `VR()` is that wheel's rings. The ring controls, presets and dot editor edit `VR()`. `#path` shows the path and leads back up. `viewClock` works out the open wheel's playhead from the top clock, so it only moves while that wheel is actually playing.
   **Per-dot sequences** (Jesse asked for these in place of the old step sequencer, after Polyend Play, on 15 Nov 2026). Every ring has `sq`, 16 slots, each null or `{on, link, s}`: `link` −1 means the dot plays its own sequence `s`; 0–7 means it plays the patch's slot `state.sqs[link]` (and `s` is kept for later). A sequence (`newSeq`, `sanSeq`) has `n` steps (1–16), `ord` (fwd, back, ping, rand, drunk), `arp`, `sm` ('note', or 'slice' on a sample), `scl` ('' = the patch scale `state.scale` {root, sc}), and per step `on`, `nt` (a scale degree), `ch` (chance), `rp` (repeats 1–8), `lv`, `cd` (chord: '', tri, sev, s2, s4, oct) and `cn` (condition: all, a:b, first, nfirst). The sequence moves one step each time the dot fires (`Engine.sqAdv`; positions live in `Engine.sqm` under the dot's key `sqKey`, a number built from the path of dots, so they survive edits). `Engine.fire` applies the dot's level, pitch and length, then the step: off, a failed chance or a failed condition plays nothing; otherwise `sqHits` lists the hits (repeats spread over the ring's average gap between dots, chord notes, Arp taking one chord note per repeat) and each is played at once or queued (`pF` = 1 marks a queued hit that plays without firing again). `Engine.play` is what the dot plays. A step's note adds to the dot's pitch: a note on an instrument, playback speed on a sample, click pitch on a click, transposition of everything inside a wheel; in Slice mode a sample step k plays the slice k slices of length `dsn` on from Start. Chord notes on a sample with Cut do not cut each other (`v.n0`). `report()` carries `sq`, each sequence's position by key; the page draws from it, and `dotList(E, t, {S, pos})` and the timeline expand the current step (`sqResolve`, `sqNow`), so the circles stay exact (tested against the engine with repeats and an octave chord). The `sqreset` message sends every sequence back to its start; a track or render also starts them from the start. The old step sequencer (`seq`: lanes, gates, glides) is still in saved state and still in the engine, but it has no controls and never plays (`seq.playing` stays false); `exampleSeq`, `sanitizeSeq` and `seqStep` remain for the engine tests. The dot pitch LFO (`pld`) still works; its button shows only on dots that already have one.
   **Pause.** The `pause` message sets `Engine.paused`: the playhead, the queue of pending dots and the clock (`tz` is taken off the time, so LFOs stand still) all freeze; voices already sounding ring out. `report()` carries `p`, and the page stops moving its own playhead.
   **Sections and the track.** `state.sections` (up to 32) each hold a whole wheel: `{name, trips, base, rings, lfo, seq}`. `state.cur` is the section on the wheel (-1: none). `state.base`, `rings`, `lfo` and `seq` are the very same objects as the current section's (`secAlias`, called before every send and save; `showSection` swaps them), so editing the wheel edits the section. `state.track` is `{items:[{s, rep}], loop}`. The Library (`inst`, `shapes`, `smpp`) is shared. In the engine, `setState` builds one patch view per section (`secS`), and `P` is the patch now playing: `S`, or a section's view while the track plays (`setTrack`, the `track` message). `trip()` runs when the top playhead wraps and moves to the next part on that exact sample; the clock restarts (`tz`) so LFOs and the step sequencer begin again with each part. At the end of a track that does not loop, the engine sets `done` and pauses. `report()` carries `l` (loops), `ti`, `tl`, `done`. Jesse decided against arranging sections as a live track (15 Nov 2026): the main window no longer has a track list or Play track, and `state.track` is kept only so saved patches stay valid. The engine's track code stays because rendering uses it: `renderParts(S, solo, …)` runs the same `Engine` class on the page, faster than real time, with a one-part track made by `partS()` (the selected section once through, or the wheel itself for one trip). `Engine.solo` lets one top ring sound alone and `Engine.raw` skips the limiter, so the four rings rendered alone add up exactly to the whole (click overlap compensation still counts every ring). Send to the arranger renders each ring that is on into its own clip; Bounce to a sample renders the mix into a sample slot.
4. **Page side.** Constants, `LFOSPEC`, `state` with `sanitizeState`/`sanitizeSeq`, and the message `bus`. The bus uses BroadcastChannel and also does direct `postMessage` to a popup or opener, de-duplicated by message id.
5. **`mountSeqWindow(host)`.** The Sequences window (`#sequencer`): one row per sequenced dot (`drawSqRows`, shared with panel 09), from `sq-rows`, with positions from `sq-pos`. Clicking a row posts `sq-open` and the main window opens that dot (`sqOpen`).
6. **`initInstrument()`.** The instrument view, audio start, visual mirror, drawing and readouts.
7. **`mountInstEditor(host, slot)`.** The instrument window (`#instrument-N`). It holds no patch of its own: it asks the main window for the instruments and sends back each change over the bus.
8. **`mountSampleEditor(host, slot)`.** The sample window (`#sample-N`). It edits the recordings themselves: it loads the slots from IndexedDB, writes each change back (`smpStore`, which resolves once the write is committed), and then posts `smp-changed` so the main window and any instrument window re-read that slot (`smpLoadOne`). It has its own plain player for auditioning, an undo stack of five (in memory, across slots), selection on the waveform with snapping to zero crossings, the edits in `OPS` (trim, delete, silence, normalise, reverse, fades, DC, gain, pitch shift by resampling, half and double speed, tune to the nearest note from the autocorrelation pitch detector, loop from selection, loop crossfade), send and split to other slots, WAV export, and recording from the microphone (in the window) or from the app's output (asked of the main window with `smp-rec`; it taps the limiter with a ScriptProcessor). A sample record is `{name, d, sr, pk, lp}`; `lp` is an optional loop as two fractions of the recording, which an instrument can adopt ("Use the sample's own loop").
9. **`mountArranger(host)`.** The arranger window (`#arrange`): audio clips on four lanes (one per ring, by default), arranged into a stereo mix. The audio of each clip is a source in IndexedDB (`rit-arr-v1`, `arrPut`/`arrGet`/`arrWipe`); the arrangement itself is JSON in `localStorage` under `rit-arr-v1` (`arrLoad`/`arrSave`/`arrSan`): `{lanes:[{vol, pan, mute, solo}×4], clips:[{id, src, name, lane, t, off, len, gain, fi, fo, body}]}`, times in seconds. A clip plays `len` seconds of its source from `off`, starting at `t`; `body` is how long the section itself lasted without its tail, and new clips are appended at the largest `t + body`. Clips are not linked back to their section (Jesse said that is not important). Tools: move (also between lanes), trim either end, split at the cursor, cut, copy, paste, duplicate, delete, gain and fades per clip, Crossfade the overlap (sets the two fades to the overlap; overlapping clips otherwise both sound), snap to clip edges and the cursor, zoom, undo (40 steps, in memory), add an audio file, Clear all. `mix()` is the one function behind both Play and Export WAV: equal-power pan, 3 ms fades at every clip edge, a soft limiter above 0.8, 44.1 kHz stereo. Sources are only deleted by Clear all.
10. **Route.** `#sequencer` shows only the Sequences window, `#instrument-N` only the instrument window, `#sample-N` only the sample window, `#arrange` only the arranger. Anything else shows the main page.

Bus messages (keep them small and JSON-serialisable):

| type | direction | contents |
|---|---|---|
| `sq-hello` | sequences window → main | ask for the rows |
| `sq-rows` | main → sequences window | `rows`: for each sequenced dot its path, key, ring, kind, slot, steps and notes |
| `sq-pos` | main → sequences window | `pos`: each sequence's step, by key; `running` (about every 80 ms while a window is open) |
| `sq-open` | sequences window → main | `path`: open that dot |
| `inst-hello` | instrument window → main | ask for the instruments |
| `inst-sync` | main → instrument windows | `inst` (all eight slots), `smpp` (the eight sample playback settings), `smp` (sample names), and the `origin` that caused it |
| `inst-set` | instrument window → main | `i`, `v` (the whole instrument, or null to clear), `origin`. `i` 8–15 sets the playback settings of sample slot `i`−8 |
| `inst-note` | instrument window → main | audition: `i`, `st`, `gate` in seconds |
| `smp-hello` | sample window → main | ask who uses each slot |
| `smp-info` | main → sample windows | `users`: for each slot, the dots and instruments that play it |
| `smp-changed` | any window → the others | `i`: that slot was rewritten in IndexedDB; re-read it. `origin` |
| `smp-rec` | sample window → main | `i`, `on`: start or stop recording the app's output into that slot |
| `smp-rec-state` | main → sample windows | `on`, `t` seconds so far, or `err` |
| `arr-changed` | main ↔ arranger | the arrangement in `localStorage` was rewritten; re-read it. `origin` |

## Look and desktop use

- The style is a lab-instrument sheet: pale ground, one blue accent for the interface, hairline rules, numbered panels (`01 Loop`, `02 Speed and tuning`, `03 Rings`, `04 Dot`, `05 Map`, `06 Library`, `07 Timeline`, `08 Sections`, `09 Sequences`, and `10 Circles` when switched on), small monospace caps labels over live readouts (`.stats`). The four rings have bold colours of their own (blue, red, amber, green), which Jesse asked for. Dot shapes show the kind: circle click, hollow circle wheel, square sample, spike impulse, diamond instrument. Keep it flat: no cards, shadows or gradients.
- Three columns from 1240 px (the wheel and speed; the rings table and the dot editor; the map and the sounds), two below that, one on a phone. The aim is that the wheel, the selected dot and the rings are all visible without scrolling on a desktop window.
- One top bar: sound, Pause and Stop all, the note readout, a small scope with its peak value, Volume, and three menus (`details.menu`: LFOs, Patch, View). A menu's box hangs from the right end of the bar. Circles is off by default (View menu, `uiPrefs.circ`).
- LFO buttons (`.lfob`) stay in the page but are invisible unless that LFO is running, Alt is held, the LFOs menu says to show them, or the screen is touch-only. Alt-click anywhere on a control opens its LFO (a capture-phase click handler). They are hidden with `visibility`, not `display`, so nothing moves when Alt is pressed.
- The Map (`drawMap`) lists every wheel in the patch as a tree and opens the one you click. The Library panel (`#pSounds`) has five tabs (Clicks, Samples, Instruments, LFO shapes, Sequences: the patch scale and the eight sequence slots); choosing a kind for a dot shows the matching tab. Detune and vibrato sit under Speed (`#tuneCtls`) and Volume in the top bar (`#tbVol`): the controls are built in `#soundCtls` and then moved.
- Window preferences (theme Auto/Light/Dark, Notes on/off) live in `localStorage` under `rit-ui-v1`, separate from the patch. Notes hides every `.hint`; it is off by default.
- The dot editor starts with what the dot plays (Plays: Click, Wheel, Sample, Instrument; Jesse had Impulse removed from the editor, but `'impulse'` is still a valid kind in saved patches and in the engine) and that kind's own controls, then Pitch, Length and Level, then Sequence (`#dSq`: Off, Own or a slot; tabs for which step value the strip `#sqCv` draws; Write, Plays, Scale), whose labels change with the kind (Note and Held for on an instrument, Speed and Slice length on a sample). Empty sample slots are drawn slim, and the instrument slots sit in two columns. The rings are a table, one line per ring, wherever the Rings panel is at least 440 px wide (a container query on `#pRings`); narrower than that they stack, so nothing overlaps. The middle column is the widest so the table fits at 1440 px. The speed preset buttons (Rhythm, Blur, Tone) were removed at Jesse's request; Sweep and Snap to notes remain. The instrument window's panels follow the signal: Source, Mix, Play mode, Envelope, Filter, Voices and output, Modulation, What the dot sends.
- The Timeline (`drawTimeline`, items from `tlItems`) is the top wheel unrolled, one lane per ring, across the current section's trips (up to eight shown), with the active LFO curves underneath. It walks the rings the same way `dotList` and `Engine.fire` do. Clicking an item selects its dot; dragging up or down sets its level. The Sections panel (`#pTrack`, `syncTrack`) lists the sections and has Send to the arranger, Open the arranger and Bounce to a sample.
- The sample window ends with the slot's Playback panels: they are the instrument editor mounted a second time (`mountInstEditor(host, 8+slot, {embed:true})`), with the panels that do not apply to a sample hidden. In either window, Alt-click on a control gives it a modulator.
- Keyboard: Space sound, K pause, 1–4 rings, ←/→ semitone (Shift = octave), N notes. Keys are ignored while typing in a field.
- Every number in a stats row must come from the same data as the plot above it. The Scope reads the signal back from an `AnalyserNode` after the limiter, so it is measured, not calculated.

## Things that must not break

- **Saved state is a public API.** It is stored in `localStorage` under `rit-state-v1`. Never rename or remove keys in `base`, `rings`, `lfo` or `seq`. LFO and lane keys such as `speed`, `F`, `r0rot` are part of it too. Add new keys and give them fallbacks in `sanitizeState`/`sanitizeSeq`. If the shape has to change incompatibly, use a new storage key and migrate.
- Starting audio: create the `AudioContext` and call `resume()` inside the tap (iOS). Fall back to the ScriptProcessor engine when AudioWorklet is missing.
- Messages to the engine must be sent straight away, not on `requestAnimationFrame`, because the instrument tab may be in the background while the sequencer window is used.
- Colours only through the CSS tokens (`T[...]` in canvas code), never literals. The `[hidden]` rule must stay, because many hidden elements have their own `display`.
- Keep the standalone document head: charset, viewport with `viewport-fit=cover`, and the safe-area padding.
